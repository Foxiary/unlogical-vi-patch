# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

A fan Vietnamese translation patch for the Nintendo Switch visual novel **UNLOGICAL** (Title ID `010068501ff9a000`, game version **v1.0.2**), shipped as LayeredFS mod romfs.

There is **no build system** — nothing regenerates `romfs/` from a source of truth. The repo contains six things:

- `romfs/Data/**` — the patched Unity binaries (`.assets`, bundles, `global-metadata.dat`). These *are* the deliverable. **36 files ship for the base title; 35 are tracked in git** — `font_jp` is gitignored and published as a release asset instead. Four of the 36 (`sprite/sprite02`, `texture/texture02`, `ui/ui01`, `sharedassets24.assets`) exist only for the DLC hub that the base game draws — its art, the two pack signs on its front screen, and its character-list row prefab.
- `aoc/<titleId>/romfs/**` — the mods for the **two DLC titles** (AOCs with their own romfs, see the trap below): `aoc/010068501ff9b001/` for DLC 1 and `aoc/010068501ff9b002/` for DLC 2, each holding `scenario/scenario_aoc0N`, `json/json_aoc0N` and `sprite/sprite_jp_aoc0N`, 3 files apiece. LayeredFS applies per title, so these ship in the release zip under their own root folders `vn-translation-dlc1/` and `vn-translation-dlc2/`, to be extracted into `contents/<titleId>/`; the workshop copies are `D:\Downloads\<titleId>\romfs`, junctioned into Ryujinx the same way as the base title.
- `exefs/669EA2FE0282C2C0EFEA4DA183419FB7.ips` — a 19-byte IPS32 code patch, and **the one file that is easy to forget**: it sits beside `romfs/`, not inside it, so a release built by zipping `romfs` alone silently omits it. v1.1 shipped that way once and had to be replaced. It raises the chapter-select hard wrap, `Chapter.get_DefaultMaxCharsPerLine` **18 → 40**, so the engine stops re-chopping lines the data already wrapped by word. Without it those 24–30 character lines get cut every 18 characters into a 18/7/18/7 zig-zag — 421 lines split mid-word, *worse* than not patching at all. Do **not** set it to 0: the same routine counts the lines it breaks to page the `StorySlider`, so zero wrapping means one page and a dead scrollbar. The filename is the NSO build id, so it is bound to v1.0.2.
- `manifest.json` — path / bytes / MD5 for all 43 (the 36 base files and 6 AOC files above **plus** the `.ips`), each tagged `"where": "repo"` or `"release"`. `tools/make_release.py` decides the zip folder from the path (`romfs/`, `exefs/` → `vn-translation/`; `aoc/<title>/` → `vn-translation-dlc1/` or `-dlc2/` per `AOC_ROOTS`), and `tools/sync_publish.py` maps `aoc/<title>/romfs/...` to the workshop `D:\Downloads\<title>\romfs\...`.
- `docs/` — reverse-engineering notes, in English (the vocabulary is Unity/UnityPy). `README.md` is in Vietnamese, aimed at players.
- `tools/` and `e2e/` — the patch scripts and the test harness; see [Tooling](#tooling) below.

Editing happens **outside this repo**: a clean v1.0.2 dump beside a working copy, patched with Python + UnityPy, then the resulting binaries are copied in. The repo is the publication surface, not the workshop — `tools/` is a record of how each file was produced, not a pipeline you can re-run to rebuild them.

## Working with the binaries

Every file under `romfs/` is binary and marked as such in `.gitattributes` — `git diff` tells you nothing. Verify by hash instead:

```powershell
# Check every in-repo file against manifest.json
Get-Content manifest.json -Raw | ConvertFrom-Json | Where-Object { $_.where -eq 'repo' } | ForEach-Object {
  $h = (Get-FileHash -Algorithm MD5 $_.path).Hash.ToLower()
  "{0}  {1}" -f $(if ($h -eq $_.md5) { 'OK  ' } else { 'FAIL' }), $_.path
}
```

**If a binary under `romfs/` changes, `manifest.json` must be updated in the same commit** — bytes and MD5 both. Nothing enforces this automatically.

Two paths are deliberately absent from git and must stay that way:

- `StreamingAssets/font/font_jp` (270 MB) — published as a GitHub release asset; `manifest.json` marks it `"where": "release"`.
- `romfs/Data/**/*.resS` — byte-identical to stock, supplied by the base game. But **twelve of the fourteen shipped `.assets` files still name their sibling `.resS`** and depend on it being present in the player's install, because untouched textures in them keep absolute offsets into it: `resources.assets` and `sharedassets5/6/9/10/11/13/17/19/21/22/24`. (Only `sharedassets7` and `sharedassets16` reference none — every texture in those was inlined.) LayeredFS resolves the `.resS` from the base game, so this works as long as the patched `.assets` is built from the *same* v1.0.2 dump.

  **This is safe only because every texture the patch *repaints* is inlined**, with `m_StreamData.path` emptied and the pixels written into the `.assets` itself — verified on all thirteen. A repainted atlas that still streamed would silently render the stock Japanese art on a player's machine, since the base game's `.resS` is what gets resolved. Re-check this after any atlas edit; it is the one way shipping without `.resS` can break.

Take a backup before every binary edit. The development convention was a gitignored `_backup/` folder with the filename suffixed by the edit that followed it (`json.prerulespacing`, `sharedassets9.assets.prearchive`), so a single step can be reverted rather than all of them.

## Architecture: where the text actually lives

Read [`docs/`](docs/) before touching data — the notes exist because these facts cost real debugging time. The load-bearing points:

**Text is spread across five unrelated storage mechanisms**, and finding a Japanese string means knowing which one you are in:

| kind | lives in | notes |
|---|---|---|
| Story prose, choices | `scenario01` → `ScenarioData` TextAsset | 17.3 M characters ≈ 23 MB of UTF-8; `text[]`/`selText[]` mapped by `loadLine[]`/`selLine[]` |
| Executed script (tag arguments) | `scenario01` → per-chapter scripts | Still Japanese by design; `[geninfo]`/`[terinfo]`/`[select_monitor]` arguments render on screen and must be patched *here*, not in `ScenarioData` |
| Terminal / Dictionary / widgets | `json` bundle | `TerminalRuleData`, `TerminalHomeAlertData`, `DictionaryData`, … |
| Twenty-one IL2CPP string literals | `Managed/Metadata/global-metadata.dat` | eight character names / name prefixes (`涼乃`→`Suzuno`, `環無`→`Kanna`, `恭介`→`Kyosuke`, plus the `ユーリ・` / `奏壱・` / `戒・` / `藍・` / `雅火・` prefixes) · `共通・`→`Chung - ` · the three season suffixes `・春` / `・夏` / `・秋` · eight UI strings (`ターミナルを開いてください`, `マップ`, `権限がありません`, `アクセス権がありません` — the SS LIST locked-story popup, whose sentence is *also* `SystemTextData` id 5, already translated, so patching the table alone leaves the screen Japanese — `現在使用できません`, `選択肢`, and the two `選択肢スキップ` settings lines) · and `。`→a space (the period the engine appends to every spoken line). Written in place with `tools/metadata_term.py`; a shorter replacement also decrements the length field in the literal table. **Three of the twenty-one are 1–2 bytes *longer* than stock** (`・春` 8→10, `恭介` 6→7, `選択肢スキップ…強制` 47→48), grown into the unused slack after their literal — `metadata_term.py` refuses any growth outright, so a longer replacement needs another route, and "the Latin form does not fit" is only true where the following literal starts immediately. Re-derive the list by diffing the literal table against stock rather than trusting this count. See [`docs/05`](docs/05-protagonist-name.md) |
| UI words that are **pixels, not strings** | sprite atlases in `scene_jp`, `ui_jp`, `sharedassets5/6/7/9/11/13/16/17/19/21/22`; sub-graphic art in `anim02/03/04/06`; the THE END cards in `cg_end` | A text audit reporting a Japanese-looking screen as clean means it is baked art. Worse in the `anim` bundles: many of those pictures are **screenshots of the game's own UI** (Terminal pages, System Message, the Question screen), so a page can look untranslated while the data behind it has been done for months — check the picture before hunting for the string |

**Every line that says the protagonist's given name exists twice.** `ScenarioData` has two boolean arrays parallel to `text[]`: `isDefaultNameAdjust` marks the copy holding the **literal** default name, shown to players who kept it, and `isCustomNameAdjust` marks the copy holding the **`[主人公]` token**, shown to players who renamed. A default-name line is drawn verbatim, so writing a token into one prints `[主人公]` on screen. Never "fix" a literal name without checking those flags first — this patch made that mistake once and it shipped visible in the short stories. The **surname** is never tokenised at all: it is fixed in metadata and Name Entry cannot change it. See [`docs/05`](docs/05-protagonist-name.md).

**The JP-slot rule.** Text tables carry JP/EN/CN slots but the engine only ever reads **JP** — the console language setting does not switch it, because only `_jp` bundles ship. Every translation is written into the JP slot, EN and CN untouched. This is why official English system dialogs sit alongside Vietnamese story text: for `SystemTextData`, usable official EN strings were copied into JP. When adding UI text, prefer the game's own official English wording over inventing phrasing.

## Traps that produce silently wrong results

These all pass offline checks and fail in game, or fail in a way that looks like the opposite problem:

- **Bundles are LZ4-compressed.** Grepping the raw file for a string finds nothing. An empty byte scan is not evidence the string is absent — search decompressed TextAssets.
- **Atlas sprites are tight-meshed.** Repainting pixels without rebuilding the mesh ships art full of holes. `sprite.image` is the check that matters; cropping the Texture2D at its rect only proves placement and will report a perfect score on broken art.
- **`uvTransform` stores the rect origin a second time.** Move a sprite via `textureRect` alone and the game samples the old slot while every offline check passes.
- **`env.file.save()` defaults to uncompressed** — pass `packer="lz4"` for bundles (a 4.1 MB bundle became 23.7 MB without it). `.assets` files save with no `packer`.
- **TextMeshPro's wrap field is `m_TextWrappingMode` in Unity 6000.0.56f1.** The old `m_enableWordWrapping` no longer exists; querying it returns `None`, which reads as "not set".
- **Real newlines (U+000A) everywhere text is displayed.** The only literal backslash-n tokens left are 89 occurrences *inside* `[command]` arguments (84) and `LoadData`'s `childJsons` (5), where they must stay literal — a real newline there ends the command line. Scripts that split on `"\\n"` return one giant line and report everything as single-line. Beware the inverse when counting: these files *are* JSON, so a real newline is stored as the two characters `\n` in the raw asset text. Parse the JSON before counting, or every entry looks like a literal token.
- **Hard line breaks were lost in translation, and the data cannot tell you so.** Stock `text[]` has 22,208 entries containing a real newline; the translation left 173, all of them leftover Japanese. The Genebark chat has since been repaired and later merge rounds carried more breaks across — `text[]` now at 552 of 39,572 non-empty entries — but roughly 21,700 prose entries are still merged into one line. Nothing is corrupt, the components auto-wrap; "the file has newlines everywhere" just describes the *format*, not this build. See [`docs/01`](docs/01-data-layout.md) for the split heuristic and its two traps (proper nouns, compound words).
- **Never blind-global-replace in `ScenarioData`.** Skip `[...]` and `【...】`, order replacements longest-first (short strings are substrings of longer ones), deduplicate shared text, and apply every edit to both `scriptText` and `text[]`.
- **`ScenarioData` holds three copies of the script and only one is drawn.** `text[j]` is what the Switch renders; `scriptText` is a second copy that **nothing indexes**, so its line count is free but an edit landing only there is invisible; `scriptText_Line` is the chapter script's lines, still Japanese, and `loadLine[j]` indexes *that* — never touch the pair. Measured drift in this build: 4 371 of 39 803 messages have `scriptText` ≠ `text[]` (stock: 0).
- **A rect is not a readable width when art overlaps it.** The ADV message box is cut diagonally at the bottom right: measured from the text's left edge the art allows 1430 px on line 1, 1364 on line 2, 1301 on line 3, while the rect handed TMP 1400. 10.5% of messages had a line running onto the dark diagonal, unreadable, with every offline check passing. Fixed by narrowing the rect to 1280.
- **The centre caption (`[textmode=5]`, `EXTRAText`) indents data lines the way the novel box does.** The engine prefixes every *data* line with a one-em indent and centres the block as a whole; a line TMP wraps gets no indent, so the two lines sit visibly out of line (IMG_7243). Narrowing the rect from 1920 to the 1764 safe margin and letting TMP wrap was tried and reverted (`ce015cc`): captions wider than 1764 px must be hard-wrapped in the data, every line ≤ 1764, which is what the two tiers of `fix_center_caption_wrap.py` do. The same rule is why the SAVE/LOAD summary box could show a stub line for those cells — one string, two widgets, and the caption wins; the second tier therefore picks, among the splits that fit 1764, the one that costs the 731 px summary box the fewest lines.
- **Boxes the engine calls a "note" paginate on the data's `\n`.** `BuildNoteLines` splits the raw string; `NOTE_TEXT_LINE` is 11 (ADV dictionary popup), 8 (ARCHIVE), 7 (chapter synopsis). TMP's own wrapping is invisible to that counter, so an over-long data line pushes its tail out of the page window and out of reach — one entry's last word had never been displayable. On those boxes each `\n` must equal one rendered line.
- **`characterSpacing` does not scale like the glyph advance.** Advance × `fontSize/pointSize`, spacing × `fontSize/100`, and the trailing spacing is not measured. The older form in `adv_layout.py` runs 7% wide on a full ADV line. The ADV box also **does not draw `「」`** — exclude them from any width sum.
- **Do not measure translation coverage by counting CJK.** Kanji character names appear inside fully translated lines. Test for kana per entry over body lines: `[ぁ-ゖァ-ヺ一-鿿]`, which also avoids the `・` bullet and `　` indent false positives.
- **The DLC is a different title, and this romfs cannot reach it.** DLC 1 is AOC `010068501FF9B001` (2.25 MB NSP); its romfs carries its own `scenario_aoc01` (`ScenarioData` with scenarios 1005–1009, 399 lines), `json_aoc01` (`DLCData_01`, the hub's character names) and its own sprites. LayeredFS applies per title, so a "DLC still Japanese" report is not a missed merge — it needs a second mod under `contents/010068501ff9b001/`. The `09_01_01`…`09_05_10` scripts inside the base `scenario01` are ordinary chapters, not the DLC. The translation lives in separate workbooks (`UNLOGICAL_DLC1.xlsx`, tabs `sd_1005`…; `UNLOGICAL_DLC2.xlsx`, tabs `sd_2005`…, whose `{sid}/cmd/000N` rows are the choice options, not terminal commands), never in `UNLOGICAL_v2`. DLC 2 is AOC `010068501FF9B002`, same layout plus one three-way choice per story. Dump with `tools/extract_dlc_romfs.py`, write with `tools/apply_dlc_sheet.py --dlc N`, repaint with `tools/fix_dlc_art.py --dlc N`; see the README section "DLC là một title khác".
- **About 480 Japanese strings in `resources.assets` belong to a different title.** `MythologyMonologue` (184), `cglist` (72), `garden` / `Garden_Master` (91 each) and `GardenEvent` (41) are Greek/Norse/Egyptian gods and a princess story — no UNLOGICAL character appears in any of them, and the translation has never touched them. The game has no such screen; confirmed in play. **The metadata is not a test**: it declares `Assets\Scripts\Garden\`, `Assets\Scripts\Quiz\MythologySelect.cs` and the literal `MINIATURE GARDEN`, because the studio ships several titles from one Unity project. Any "what is still untranslated" sweep must exclude those five assets or it reports 480 phantom items. (`箱庭` on its own is not a tell — it is in the OP lyrics.)
- **A field can be dead on one screen and live on another.** The SOUND tab draws each character's name into the slider-strip sprite, so `ConfigVolumeData.label` looks unused — but the INFO bar at the bottom composes that same field with `SystemTextData` id 71 (`"'s volume settings"`). Translating only the art left the screen reading `MIYABI` on the slider and `雅火's volume settings` underneath. Check every surface a string feeds before calling it dead.

## Tooling

`tools/` and `e2e/` are committed as a **record of how each binary was produced**, not as a pipeline. Every script hardcodes absolute paths into the author's working copy (some into a temp scratchpad that no longer exists), so nothing here runs unmodified on a fresh clone. Read them for the geometry, the field names and the reasoning; adjust the paths before running anything.

- `tools/fix_*.py` — one script per patched screen. Each states in its docstring which file and which objects it touches, and most take `--write` (dry-run by default).
- `tools/adv_layout.py`, `tools/_advances.json` — the ADV line-fitting model and the per-glyph advance table it was calibrated against. Note the caveat in `docs/02`: it uses the older `(advance + spacing) * fontSize/pointSize` form and errs slightly wide.
- `e2e/run.ps1` — drives a real Ryujinx session with Win32 scancode injection, classifying each frame with `e2e/checks/identify.py` and navigating by pixel. Screenshots land in a gitignored `e2e/out/`.
- `e2e/checks/check_scripts.py` — **the one check worth running on every write to `scenario01`.** It asserts that all 143 executed chapter scripts still have the same command-keyword sequence and scene labels as stock. It caught a dropped `[env カメラ移動 xpos=0 ypos=0 zpos=0 time=0]` in `00_04` that no text diff would have shown.
- `e2e/checks/check_chapterdata.py` — eight static assertions over `ChapterData` (entry keys, label drift vs stock, no `<size=>` tags, wrapped at ≤18 characters).
- `tools/apply_sheet_cells.py` — pulls a chosen set of cells down from a sheet snapshot, three-way against the previous snapshot, with the guards below. `--match=<regex>` keeps a terminology round from dragging everything else along.
- `tools/check_layout_breaks.py` — diffs the packed bundle against a pre-merge backup, per string, on the two things a flat sheet cell cannot carry: newline count and indented-line count. Losing either fails. Run against the 15 Aug baseline it found five regressions nobody had noticed, including two messages left **empty** where the Japanese has `「…………」`.
- **Five layout fixers that must be re-run after every sheet merge**, because the sheet stores each cell as one flat line and the merge flattens their work: `fix_adv_wrap.py` (checks nothing runs under the box art), `fix_novel_list_wrap.py` (numbered rules, hanging indent), `fix_dictionary_wrap.py` (dictionary body to the popup's 586 px), `fix_ellipsis_break.py` (`... ...` breaks the line), and `fix_jp_sentence_break.py` — **the one that reads the Japanese**: where the JP puts the next sentence on its own line, the Vietnamese does too, as long as every segment but the last still fits one line. Each takes `--check` and exits non-zero, so they belong in the post-merge gate next to `check_scripts.py`.
- **The merge does not create line breaks; only these fixers do.** `apply_sheet_cells.carry_breaks()` never looks at the Japanese and never looks at punctuation — it flattens the build cell, aligns it to the new wording with `difflib` **character by character**, and moves each `\n` to the space it maps onto; all-or-nothing per cell, and it refuses (`không đặt lại được N ngắt dòng`) when it cannot place them all. `difflib`'s matching blocks are monotonic, so **a cell whose clauses were swapped can never be carried** — the round `(99)` cell `105/txt/0161` (`Tôi nhớ là khoảng 30 phút sau… / Khi tôi kết thúc…` → the sheet reordering it to follow the JP) mapped the newline position to nothing at all. That is not a bug to loosen: the layout the merge carries is mostly *pixel* wrapping from `fix_adv_wrap`, which has no relation to punctuation. The right recovery is to leave the cell **flat** and let `fix_jp_sentence_break.py` decide from the Japanese — its first guard is "the Vietnamese must contain no `\n`", so a hand-placed break locks it out. (Hand-placing that break was measured to give the identical result here, but it cost the tool its turn.)
- `tools/fix_novel_prose_break.py` — the novel-mode counterpart of `fix_midphrase_break.py`, which deliberately skips the novel region. `Message(Novel)` (1400 px) indents every *data* line one em and leaves TMP-wrapped lines flush, so a hand-placed break in the middle of a phrase is harmless only while the data line before it fits; once a merge lengthens that line, its tail drops onto an un-indented line and the next hard break indents again (`"Kiến` / `thức cơ bản"` in IMG_7238). The script joins the mid-phrase breaks of the offending message and keeps sentence-boundary ones; `--check` belongs in the post-merge gate.
- `tools/fix_adv_box_width.py` — the one component patch of that family: `level10` pid 564/581 `m_SizeDelta.x` 1400 → 1280, bytes in place, size unchanged.
- `tools/fontcache.py` — every tool that paints text onto sprites needs real `.ttf` files; the first ones lived in a Claude scratchpad that is gone. This extracts `m_FontData` from the Font assets in `ui_jp` into the gitignored `_fonts/` on demand (`ttf("FOT-NewRodinProN-DB")`, `ttf("FOT-DotGothic12Std-M")`). `fix_key_prompts.py` uses it; `fix_music_key.py` and `fix_movie_total_plate.py` still point at the dead path and would need the same change before they can run again.
- `tools/fix_dlc_art.py` — the DLC 1 art (thumbnail subtitles, the Caution screen, the CHAPTER name windows), built from the stock AOC dump and the stock base dump through `keyart.Container`. Its docstring and the README record four measurement lessons; the transferable ones are that colour-keyed erase masks miss anti-aliased fringes (wipe every non-white pixel inside the text box instead, or dilate the mask), and that the pixel font must be drawn with anti-aliasing off (`fontmode = "1"`) or it comes out thin and grey next to the game's own dots.
- `tools/fix_dlc_top_menu.py` — the two pack signs on the Download Contents front screen (`ＤＬＣ 第Ｎ弾` → `DLC N`) plus its 3-line "not purchased yet" window, in `ui/ui01` / atlas `DLC_TOP`. Two transferable lessons. **A screen can be missed because its bundle was never opened**: every other `UL_dlc_*` group had been translated, but `ui01` was not on the shipped list, and no TextAsset anywhere contains `第1弾` — the only string hit is the already-translated `SystemTextData` id 24. Sweep by *asset name* (`dlc` in any Sprite/Texture2D/GameObject name across the whole dump), not only by string, or baked art like this stays invisible. And **when the new string is a subset of the old one, move the game's own glyphs instead of re-rendering**: cut the `ＤＬＣ` and digit ink out, erase the line, paste them back re-centred — no font, so no size/stroke/colour drift. Erase guards: count the brightest *run* along a row or column rather than total bright pixels (a grid line is a run, ASTC decode speckle is not — the mint sign has a grid line exactly 3 px under the text), and give a Vietnamese line more vertical room than the Japanese it replaces, because diacritics sit ~6 px above cap height. Repainting kept the atlas ASTC 4x4 (+65 KB, max re-encode loss 13/255 on 3 pixels).
- `tools/fix_nameplate_wrap.py` — the ADV speaker nameplate is a 500 × 70 rect (`level10` pid 650/699) with auto-sizing **off**, word-wrap **on** and overflow visible, so a name too wide never shrinks the way the message box does: it wraps to a second line and spills out of the plate onto the art. Ten names were shortened in the data instead. `--check` measures every nameplate, not only those ten, and exits non-zero. Do **not** add it to the post-merge gate above — nameplates are not sheet-owned, see below — but run it after any hand edit to a speaker name. Two things it had to get right: the nameplate renders at ~47.5 px, not the 42 the scene declares (the game resizes it at runtime, so the model is calibrated against a real capture, not against `m_fontSize`), and the 289 account-style nameplates (`【Kai Munakata@k_munakata2150】`, 893 px) live inside `[chat start] … [chat end]` and are drawn by the Genebark chat widget, which is far wider — counting them as ADV nameplates produces nine false alarms.

- `tools/check_term_consistency.py` — the only check whose axis is the **term**, not the cell or the sentence. Every other gate compares one cell against its own counterpart, so a Japanese proper noun rendered two ways across two different cells passes them all; that is how `黒服` shipped as both "Hắc phục" and "Áo đen", and how `舞茉` was "nấm Maitake" in one scene and "nấm lá sen" in another. It pulls candidate terms from the **stock** text — anything inside `『』` and both halves of a ruby tag — then scores each Vietnamese rendering by **coverage** and lists the cells the winner does not cover. It is advisory, not a gate: it exits 0 and the six standing entries have each been checked by hand. Three noise classes are filtered, documented in its docstring; re-read that before "fixing" a new entry, because two of the three were bugs in the checker rather than in the translation.

- `tools/fix_item_name_case.py` — `ScriptDialogData` (the 18 "Đã nhận được 『…』" item pop-ups) **is not on the sheet at all** — no tab, no id, verified against a full 40 262-cell snapshot — so every merge skips it and a wrong item name there can never heal from upstream. It shipped `『Trái tim thiên sứ』` while eleven lines of dialogue said `Trái tim Thiên sứ`, and the pop-up floats directly over those lines. The "correct" spelling is **not** hardcoded: the script counts both forms in `ScenarioData.text[]` and refuses to act unless one clearly wins. `--check` belongs in the post-merge gate precisely because the sheet cannot reach this file.

- `tools/fix_terinfo_unquoted.py` — the one `[terinfo]` banner left in Japanese, and the reason it survived every sweep: **it is the single command in the stock scripts whose `text=` argument carries no quotes**. The sheet exporter only matches `text="…"`, so `sID 71` @12609 has no sheet row at all (that is also why the `cmd` id numbering lines up 116/116) and `apply_sheet_cells.py` can never reach it — same "the sheet cannot get here" class as `fix_item_name_case.py` and `fix_system_text_case.py`. The wording is copied verbatim from line 744 of the same script, which announces the same five losers, so nothing new is invented; quotes are added because a bare value stops at the first space. The line lives in three places (chapter script `00_03` plain, `ScenarioData.scriptText` and `scriptText_Line` JSON-escaped) and all three are rewritten on the **raw text**, never by parsing and re-dumping 17 MB of JSON. **Its own safety check could not use a reverse `str.replace`**: the replacement string already exists in the file (line 744), so reversing would turn that correct line Japanese and report a false alarm — the script records the **offset** of each replacement and rebuilds the original positionally instead.

- `tools/fix_line_start_case.py` — the line after a hard break starts with a capital. 6,860 of the 7,390 hard breaks in `text[]` already did; this closes the other **427** (426 right after `...`, 1 after a full stop). Breaks after a comma, after `―`/`;`, or mid-phrase are **left lowercase** — the sentence has not ended there, and they belong to `fix_midphrase_break.py`. The rule is flat by the owner's call (3 Sep 2026): the 120 lines opening with a conjunction get a capital too (`Dù biết là thế giới game... / Nhưng mình…`); the "exempt conjunctions" variant was offered and rejected, and it would not have fixed the reported line anyway (`cứ` is one). Two things it has to get right: the rule attaches to a break **in the data**, never to a line on screen — the box directly above the reported one in `IMG_7248` is a TMP soft wrap with no `\n` at all and cannot be reached; and the first character of a line is often not a letter — `[主人公]` (already a proper name at runtime, skip the break), `[dic no=N text=X]` (capitalise inside `X`, never touch `N`), `[base'ruby]` (capitalise `base`), an opening quote or `―` (skip past it), a URL (skip). Counting without resolving those makes 10 of 11 "lowercase after a full stop" hits false. `selText`, `resources.assets` and both DLCs hold none; the chat bubbles in `json` (`GenebarkChatMainData.content`, 31 cells / 29 strings) ride behind `--json`. **The `\n` in a table is not always a sentence boundary, and this rule is wrong wherever it is not**: in `json` only the chat table flows freely, so that half runs off an allowlist — a blind sweep hit `ChapterData.synopsis`, whose newlines are the 18-character hard wrap the game's own code enforces (`check_chapterdata.py`), and `TerminalRuleData`/`DictionaryData` paginate on `\n`. In `scenario01` the same two width-wrapped regions were checked against the 428 edits: `[textmode=5]` captions overlap 0, and the 13 novel-region hits are all two-line prose, no list blocks. Idempotent, `--check` exits non-zero — it belongs in the post-merge gate, because the sheet supplies the wording and a merge can flatten the capital back. Run `fix_adv_wrap --check` and `fix_chat_wrap --check` after it: capitals are wider than lowercase.

- `tools/fix_system_text_case.py` — case fixes to the English wording that sits in `SystemTextData`'s **JP** slots (`resources.assets`), e.g. `Downloadable Content` → `Downloadable content` on the "DLC applied" toast, id 7. The sheet cannot reach `resources.assets` at all, so a hand edit here is permanent and needs no post-merge gate. Because a case change is the same byte length, it **patches the file in place instead of re-packing** — UnityPy would otherwise realign every object to 8 bytes (stock is 16) and move offsets that have nothing to do with the edit. Three things make a byte patch land wrong, and all three were hit: the anchor must include the `"JP": ` key (the string itself occurs twice — JP and EN, and EN must not change), `str.index` counts characters while the file counts bytes (248 bytes of drift here, from the CJK ahead of it), and the file stores the **JSON-escaped** form, so a newline is `\` `n`, not `0x0A`. Verified by reloading: 92 entries intact, exactly one JP slot changed, `cmp -l` shows one byte.
- `tools/marquee_lib.py` + `fix_music_title_marquee.py` / `fix_recollection_marquee.py` / `fix_section_title_marquee.py` / `fix_dlc_list_marquee.py` — the four one-line boxes that overflow (MUSIC track title, Ending List rows, section title, the DLC character-list rows) now **scroll** using a component the game ships but never instantiated: `AutoScrollText` (`Assets/Scripts/Auto/`, MonoScript `globalgamemanagers.assets` pid 1187, 0 instances anywhere). It needs a `RectMask2D` on its own GameObject, moves `targetText.rectTransform.anchoredPosition.x` from 0, and only scrolls when `preferredWidth > mask.rect.width`; it hooks TMP's `TEXT_CHANGED`, so it re-arms itself whenever the game sets the text. Adding a class a file has never seen is data-only: in a no-typetree file the type entry needs `script_id = MD4(class+namespace+assembly)` and `old_type_hash = MonoScript.m_PropertiesHash` (formula verified against every existing entry); in the `ui_jp` bundle the MonoScript lives inside the CAB and the type entry needs a hand-assembled typetree node, **and every new object must be inserted into the `AssetBundle.m_PreloadTable` range of its prefab, MonoScripts ahead of the components that use them** — otherwise the component deserialises before its script is loaded and comes up as a missing script (the first section-title build shipped that way: `ContentSizeFitter` alive, `LayoutElement`/`AutoScrollText` dead, title hugging the left edge). Two geometry rules were paid for in screenshots: the mask must cover the **text area only** (a TMP left margin under the mask lets scrolling text run into it), and "centre when it fits, left-align when it scrolls" is done with `ContentSizeFitter` + `LayoutElement.minWidth`, never with TMP alignment, because `StartScroll` forces `x = 0`. Every script re-loads its own output and refuses to write unless all untouched objects are byte-identical; UnityPy re-packs objects at 8-byte alignment (stock uses 16), so the file shrinks a little — `level17`/`level22` shipped that way. All four scroll after a `startDelay` of **0.5 s** (built at 1.5 s, lowered on 3 Sep 2026); the four `fix_*_marquee.py` refuse to run on a file they already patched, so a timing change goes through `tools/set_marquee_delay.py`, which rewrites the one float at offset 48 of each `AutoScrollText` (in place for `.assets`, via re-pack for the `ui_jp` bundle) and verifies nothing else moved.
- `tools/fix_music_title_case.py` — `MusicData.title` in ALL CAPS. The title box uses a TMP **SDF-Dynamic** font (empty character table, glyphs rasterised at runtime), so "does the font have the glyph" means reading the cmap of the source `Font.m_FontData` (`sharedassets13` pid 48 — ULPixel in this patch, which has every Vietnamese capital; stock DotGothic lacks 51). The script refuses to write if a needed glyph is missing.

**The chapter-select synopsis wraps at 18 characters in game code, counting rich-text tag characters.** Editing the TMP component or inserting `<size=>` tags does nothing — three patch rounds were spent rediscovering this. The data itself must word-wrap at ≤18. `check_chapterdata.py` enforces it.

### The translation source

**Two things the sheet does not own, and a merge therefore cannot undo.** Speaker nameplates: the `sd_*` tabs carry the *Japanese* nameplate in column B as a caption with no translation column beside it, and the reader only ever looks at columns C and D — so `ScenarioData.talkName` exists only in the build, and nothing shortened there needs pushing back upstream. And `scenarioID` 0–12: those index the first thirteen keys of `scenariolist`, every one of them a developer test script (`01_test_live2d_01..03`, `sample1..3`, `UL_Live2d_test_sample`, `UL_test`, `UL_test_select`), which is why the sheet's first tab is `sd_013`. They are still entirely Japanese — 1,235 cells in `UL_Live2d_test_sample` alone — and unreachable: `ChapterData`'s 43 entries never name them, `SceneLabelList` / `SceneReplayData` / `MapData` hold 0 of their 31 labels, no real script jumps into those labels, and `global-metadata.dat` contains none of their names. `UL_test` is literally a QA checklist addressed to the publisher (`こちらの演出やアニメーションで問題ないかご確認お願い致します`). Do not count them as untranslated.

Prose comes from an upstream Google Sheet (`UNLOGICAL_v2`), but the working copy is also hand-edited directly, so **syncing is a three-way merge, never a copy**: base = the previous sheet snapshot, theirs = the new one, ours = the packed `text[]`. Normalise before comparing or the diff drowns — a raw compare showed 12,286 differences where ~500 were real. Two guards must survive any "just take the sheet" instruction, because they protect lookups rather than style: refuse a cell whose `[command]` tags differ, and refuse one where `[主人公]` appears on only one side.

Four more guards were earned the hard way, all implemented in `tools/apply_sheet_cells.py`:

- **Separate lookup keys from display text inside `[...]`.** A raw multiset compare refuses legitimate work: both halves of a `[base'ruby]` tag are display text, so a swap (`[Người lựa chọn'Selector]` → `[Selector'Người lựa chọn]`, 72 cells) and even the tag's removal are valid — the latter only if one half survives in the sentence, otherwise it is a truncated edit. For `[dic no=N text=X]` only `N` is the key, and it must never change or vanish.
- **Detect "the translation landed in the wrong cell".** Group the round's changed cells by their new Vietnamese text; if a group holds two cells whose *Japanese* differs, the one whose new text is far from its own old text was pasted over. Caught a snapshot where `71/txt/0379` carried `0377`'s translation. Merge such a cell against the snapshot *before* the damaged one.
- **Compare on flattened text** (`\n` → space). The build keeps hard breaks and the sheet does not, so a verbatim compare reports "both sides moved" for cells that are already correct.
- **Take wording from the sheet, layout from the build.** Line breaks are carried across with difflib; for `TerminalRuleData/rule_body` rows the leading `　` of each build line is restored, because the sheet has decayed every fullwidth indent to one ASCII space and every blank spacer line to a lone space. That tab also repeats each id once per page — the k-th row is `content[k]`, and keying by id collapses 39 rows into 21.

Terminology is decided by counting, not taste: a dictionary entry's title must be the word the player actually reads, measured over the *main* text of `text[]` with ruby halves stripped. That is how `Spirit`, `Plugin`, `Matching`, `Deep Learning` and `Mainframe` came to lead their entries while `Ban điều hành` stayed Vietnamese (271 uses against 141 for "Operator").

## Version coupling

The patch is built against **v1.0.2** only. `global-metadata.dat` offsets differ between 1.0.0 and 1.0.2, so applying the metadata patch to another version crashes or garbles text. Confirm the emulator has update `v131072` selected before shipping anything that touches metadata.

Reverting is just deleting that one file from the mod romfs — but it reverts **all twenty-one** literals at once, not only the name. Dropping it brings back the `。` the engine appends to every spoken line, and `共通・` in place of `Chung - `.

Build target for reference: Unity **6000.0.56f1**, IL2CPP, Switch (Tegra) ASTC textures, UnityPy 1.25.

## Conventions

- Almost every question in `docs/` was settled by **diffing the patched file against a stock dump**, not by reasoning. Keep doing that.
- Established romanisations are taken from the game's own asset names and already-translated widget text, never invented; story convention is surname-first. The list is in `docs/05-protagonist-name.md` — reuse it rather than transliterating afresh.
- Markdown and JSON keep LF endings (`.gitattributes`).
- Known-outstanding Japanese items are tracked in the README's "Các phần tồn đọng đã biết" section; update it when one is closed.
